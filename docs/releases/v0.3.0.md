# flixw-metrics v0.3.0

This release expands compiler compatibility from one Flix generation to six adapter families and
adds typed effect context without turning it into unsupported policy.

## Highlights

- Flix 0.60.0, 0.61.0, 0.65.0, 0.66.1, 0.67.1, 0.67.2, 0.68.0, 0.75.2, 0.75.3,
  and 0.76.0 are verified. Six isolated adapters are selected by bytecode-derived linkage
  requirements rather than compiler version strings.
- Flix 0.76.0 is the current compiler pin. Polymorphic effects remain atomic capabilities while
  native JSON can retain each constructor's compiler-rendered type arguments separately.
- Per-definition handler facts report handler literals, handled operation clauses, the widest
  handler, and direct resumptions. They do not change cognitive complexity or create findings.
- Full native JSON includes typed effect declarations with source locations, type-parameter counts,
  source-ordered operation names and arities, plus derived operation counts and maximum arity.
- The compiler-neutral SDK, cache wire format, and native report schema carry the new facts. The
  wire format is version 12 and the native JSON schema is version 32; old measurement caches safely
  miss. Text, Markdown, SARIF, thresholds, and existing effect-count semantics are unchanged.
- Adapter sources and Mill targets now share one `adapter` hierarchy, while each family remains
  compiled in isolation against the oldest verified compiler in that family.
